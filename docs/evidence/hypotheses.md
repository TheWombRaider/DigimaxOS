# Hypotheses

A hypothesis is a claim we act on provisionally. Each one records how it will be tested and what
would falsify it. Close a hypothesis by moving its result to [findings.md](findings.md).

| ID | Hypothesis | Basis | Test that would settle it | Status |
|---|---|---|---|---|
| H-001 | The main SoC is an SPCA536 (or 536A), and "SPCA535" in the block diagram is a drafting error or an older revision label. | S3 section titles, `MEGA536` label | Read the chip marking from a **donor** board photo, or match update-file strings | open |
| H-002 | The stock SD host path is SDSC-only: it never sends CMD8 / HCS, so SDHC cards stay busy in ACMD41 and are reported as card errors. | Era (2005; SDHC introduced 2006); `HostPolicy.legacy()` model | Insert a scratch SDHC card and record the stock error; later, find the ACMD41 argument in firmware | open |
| H-003 | Stock firmware supports FAT12/16 only. A 2 GB SDSC card (FAT16, 32 KiB clusters) may work; FAT32 will not. | Era; 512 MB guarantee | SD-01 test plan with 1 GB and 2 GB SDSC cards, FAT16 vs FAT32 formatted on the host | open |
| H-004 | "F7.0" is a second fixed aperture plate or ND filter moved by the LB1846M motor driver, not a continuously variable iris. | Two discrete values; motor driver present | Exposure baseline: an exact 2.0 EV difference with *no* depth-of-field change suggests ND; a DoF change suggests an aperture plate | open |
| H-005 | The Night-mode routines already accept arbitrary (shutter, aperture) pairs. An M mode can reuse them, adding ISO selection and turning off auto override. | S2 | Baseline: is ISO selectable in Night mode? Do the settings persist? Do EXIF values match the selection? | open. Narrowed by EXP-0004: Night mode only offers 8 s to 1/8 s, so it covers the slow end only |
| H-006 | The update file `MEGA536` contains the application firmware but possibly not the boot ROM, the EEPROM calibration or the NAND bad-block map, so it alone is not a recovery path. | Spec 7B; S3 copy-via-camera procedure | Obtain the file; compare its size with 16 MB NAND / boot ROM; look for container headers | open |
| H-007 | The camera writes the update file through its USB mass-storage path to **internal flash or the card**, and the bootloader checks for it at power-on. That would explain why a card reader "does not work": the file may need to be in internal memory. | S3 "Do not use card Reader" | Observe which LUN is exposed with *no card* inserted (internal 16 MB) | **partly supported**: with no card, internal memory is the only LUN (EXP-0002, F-026). Whether the bootloader reads the update from there is still open |
| H-008 | The CPU is 8051-family (8032), like the SPCA533A. | S12 (related chip) | ISA determination from a firmware image, using several independent clues (reset vector, call/return statistics, code cross-references) | **weakened**: 32-bit pointers (F-046) and R3000 reports (F-055) |
| H-009 | `M4051S-0525` encodes platform `M405`, revision `1S` and a build date of 2005-05-25. `-0520` (if real) is an earlier build. | EXP-0003, S16, S17 | Collect `Software` tags from many A402/D402 photos online (EXIF of public photos), and match strings in an update file | open |
| H-010 | The about 3.73 MiB of NAND not exposed over USB holds the firmware image (and/or a boot copy, settings and bad-block spares). The firmware is therefore NAND-resident and loaded to SDRAM at boot. | F-027; S12 pattern (flash→RAM copy) | Compare with the size of an update file (#1); donor NAND dump (#4) | **strengthened**: the reserve table puts 215 blocks (809–1023, 3.36 MiB) outside the LUN (F-047) |
| H-011 | Sectors 1–56 of the internal-memory LUN (before the partition) hold camera-written metadata rather than leftover data. | EXP-0003 (non-zero) | With approval, read and characterise them (no user data lives there) | **confirmed**: FTL reserve header and tables (F-046) |
| H-012 | The auto-exposure path drives the shutter at speeds up to 1/1000 s through a routine that also accepts arbitrary user-chosen values, so an M mode can offer 1/15 to 1/1000 s. | S1 range; F-044 | Program-mode captures across bright scenes: EXIF ExposureTime distribution and timed-LED measurements; later, locate the routine in firmware | **supported**: AE writes fine-grained, non-stepped times (F-048); fast end still unobserved |
| H-013 | The CPU is a MIPS R3000-compatible 32-bit core (little-endian), and `0xAC05xxxx` are uncached KSEG1 addresses of SDRAM structures. | F-046 pointer table; S18/S21 R3000 reports (F-055) | Independent clues from a firmware image: MIPS reset/exception vectors (0xBFC00000 / 0x80000080), instruction statistics, `lui`/`addiu` address pairs | open (**moderate**) |
| H-014 | The SPCA536 boot ROM provides a USB ISP mode (the `USBISP.BIN` path) that can read and write NAND, including the RSV region, without working application firmware. That would satisfy R4. | F-056, F-057 | Find documentation of the entry method (strap pin or key combination); verify **read-only** behaviour on a donor first; never on the reference unit before gate G2 | open, **weakened** by F-059: on the sibling SPCA533A, ISP is firmware-driven |
| H-015 | The SPCA536's SD host is the same kind of firmware-driven native command engine as the SPCA533A's, so **SDHC support is a firmware-only change** (CMD8, ACMD41 HCS, CCS-aware block addressing, CSD v2, FAT32), with no hardware barrier. | F-058; S5 | Locate the SD register block and the CMD8/ACMD41 code paths in a firmware image; observe stock SDHC failure (H-002) | open (**promising**) |
| H-016 | The A402 boots from an external parallel **FlashROM** (NOR) holding the code. The NAND RSV region holds resources (fonts, images, sounds) and/or a code copy. The `MEGA536` update rewrites the FlashROM. A donor's FlashROM, read and written out of circuit with a standard programmer, would be an independent recovery path (R4). | F-060, F-012, F-047, S3 | Transcribe the schematic p.55 (#13) for the FlashROM part number and bus; read a donor's FlashROM | open |
